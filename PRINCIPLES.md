# Resume System Principles

## 1. The pre-training metaphor stays backstage

The resume should read like a strong conventional professional resume, not like an AI-themed creative essay.

Use the metaphor internally to answer:

environment
→ difficult problem distribution
→ decisions / actions
→ feedback
→ capabilities trained
→ transfer to target JD

Do not force words such as "pre-trained", "fine-tuned", "weights", or "model" into normal resume bullets unless a specific context genuinely calls for them.

## 2. Facts before bullets

Every experience record preserves raw facts before polishing:
- context;
- problem;
- constraints;
- user's personal ownership;
- actions;
- collaborators / AI contribution;
- evidence;
- outcome;
- feedback;
- what changed;
- transferable capabilities.

Resume bullets are generated downstream.

## 3. Ownership must be explicit

Never convert:
- AI research into "I researched" without qualification;
- team output into sole ownership;
- simulated economics into realized business results;
- portfolio prototypes into shipped products;
- public evidence into user interviews.

The system should favor strong honest claims over inflated claims.

## 4. Evidence hierarchy

1. Real external outcome — revenue, adoption, publication, release, measured performance, accepted work.
2. Operational artifact — working product, model, prototype, reproducible analysis.
3. Decision evidence — evidence changed a real scope, design, or resource decision.
4. Structured analysis — useful but weaker alone.
5. Assertion — never sufficient by itself.

## 5. Tailor by selection, not fabrication

A JD-specific resume may:
- reorder sections;
- select different experiences;
- change emphasis;
- translate terminology;
- compress or expand bullets.

It may not create experience that did not happen.

## 6. One page is the default

For campus / early-career commercial roles, target one page unless a specific employer or context clearly benefits from more.
