# 个人主页持续更新交接

## 用途与上游

用户于 2026-10-16 要求把已经上线的中英文个人主页整理为可交给任意新对话继续维护的 GitHub 交接，并提供格式化提交材料模板。上游是仓库根 `AGENTS.md`、`START_HERE.md`、事实层 `PROFILE.md`/`experience/`、公开稿 `publication/`、网站 `site/`；2026-10-08 的英文版合并与上线事实来自 PR #28 及当次本地发布验证。

## 文件地图

- `README.md`：**规范入口**。当前页面/项目、来源映射、更新 SOP、校验与发布边界。
- `SUBMISSION_TEMPLATE.md`：用户或下一对话填写的一份变更材料。模板本身公开，含未公开材料的填写副本不得直接提交公开仓库。
- `RELEASE_2026-10-08.md`：英文版首次上线的历史部署与验证记录；以后发布须另写当次记录。

## 当前决策

- 保持一个网站、既有页面结构及中文 `/` + 英文 `/en/` 的配对；新材料先查事实与公开许可，再改公开稿与译稿。
- 模板是**提交信息格式**，不是网站可直接导入的数据格式。现有静态路由和输出清单对新增案例仍需代码适配。
- 2026-10-08 的应用状态、外链和上线结果都是有日期的快照；下一次发布前重新核验。
- 本文件夹和根入口是持续维护文档，旧轮次审计不删除或重写。

## 交接状态

文档经仓库源码与已有发布记录核对后提交到 GitHub 默认分支。新对话从 `README.md` 开始；若用户仅给出零散新材料，先整理进模板，缺失项标“未知”，不要补造事实。是否上线以该次用户请求为准。
